# Контроль сроков

Следит, чтобы обещания контрагентов не терялись. Работает поверх `ledger/agreements.jsonl` (скилл `object-ledger`).

## Когда использовать

- Автоматизация «deadline-check» (два раза в день: 09:00 и 17:00)
- Пользователь: «кто мне должен?», «что просрочено?», «напомни Сидорову»
- Пора обновить статусы договорённостей

## Алгоритм проверки (cron-джоба)

1. Прочитай `ledger/agreements.jsonl`, выбери `status=open`.
2. Классифицируй:
   - **просрочено** (`due` < сегодня) → обнови `status` на `overdue`;
   - **горит сегодня/завтра** (`due` ≤ завтра) → в срочную группу;
   - **без даты** и старше 3 дней с `created` → в группу «уточнить».
3. Для каждого — состави **готовый текст сообщения** (формат ниже).
4. Отправь владельцу сводку одним сообщением (или включи в утренний дайджест, если запущен оттуда).
5. Если автоматизация одноразовая (`--delete-after-run`) — не создавай повторно.

## Готовый текст напоминания

Пиши так, чтобы владелец мог переслать без правок:

> Имя, добрый день! По договорённости от <дата>: <what>. Срок — <due>. Напоминаю и уточняю: всё ли идёт по плану?

Для просроченного — мягче, но прямо:

> Имя, добрый день! Просрочен срок по <what> (<due>). Когда сможете закрыть вопрос?

Никогда не отправляй сообщение контрагенту сам — только владельцу на согласование.

## Обновление статусов

Когда пользователь подтверждает («сделано», «оплатил») или приходит подтверждение в чате — пометь договорённость `done` (перепиши файл через полный read-modify-write, сохранив порядок строк). Если срок сдвинули — обнови `due` и пересоздай напоминание.

## Правила

- Таймзона — из конфига агента (`userTimezone`), даты сравнивай в ней.
- Не дублируй напоминания: у одного `id` договорённости одно активное напоминание (проверяй `openclaw automations list` по имени `due:<id>`).
- Пустой список просроченных — тоже результат: «✅ Просроченных нет».
