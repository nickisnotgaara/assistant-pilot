# Проверка пилота (verify-pilot)

После любого изменения скиллов, tg-ingest или конфига прогоняй автотесты и показывай отчёт.

## Когда использовать

- Пользователь просит «проверь», «протестируй», «всё ли работает»
- Изменены скиллы, ledger-форматы, tg-ingest, конфиги OpenClaw
- Перед сдачей/отчётом пользователю

## Как запускать

```bash
python C:/Users/User/Desktop/openclaw-pilot/tests/acceptance.py
```

Или выборочно: `python .../acceptance.py 2 3 8`.

Скрипт сам гонит 8 сценариев (карточка объекта, договорённости, черновик с кнопкой,
дайджест, расходы, документы, контекст переписок, созвон+напоминание) и печатает
таблицу PASS/FAIL с доказательствами. Результат пишется в `tests/last-run.json`.

## Правила

- Не подменяй прогон ручными проверками — вердикт выносит скрипт.
- FAIL = чинить корень проблемы, потом перегонять весь прогон.
- В отчёте пользователю: таблица PASS/FAIL + что чинил.
- Сценарии используют тестовые метки `{RUN}` — не считай их реальными данными.
